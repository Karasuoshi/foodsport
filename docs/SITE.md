# Сайт: ТЗ и устройство

Статический Next.js 14 (`output: "export"`, `basePath: /foodsport`) на GitHub Pages. Серверной части нет: браузер ходит в Supabase напрямую с токеном владельца.

## Принципы
- **Сайт только для просмотра.** Форм ввода, кнопок «добавить», «удалить» и чекбоксов нет. Единственная форма — вход, один раз на устройство.
- **Ничего не обнуляется.** Все шесть таблиц загружаются одним пакетом, и экран обновляется, только когда пакет пришёл целиком. При сбое на экране остаются последние данные и появляется плашка «Нет связи». Последний успешный снимок хранится в кэше браузера отдельно для каждого аккаунта и показывается сразу при открытии.
- **Обновление** каждые 15 секунд, пока вкладка открыта, а также при фокусе окна и восстановлении сети.
- **Сессия:** токен обновляется сам. Сбой сети не выкидывает из аккаунта, выход происходит только если Supabase отверг токен.
- Тексты на сайте — короткий нормальный русский. Без технических пояснений и служебных формулировок агентов.

## Экран (сверху вниз)
1. Дата: стрелки и кнопка «Сегодня».
2. Четыре метрики дня: ккал, белок, жиры, углеводы. У ккал и белка — полоса прогресса к ориентиру из `settings`; превышение больше чем на 5 % подсвечивается.
3. Питание: таблица позиций (порция, КБЖУ), итог, оценка дня и комментарий из `day_reviews`, статус дня (закрыт / не закрыт / нет записей).
4. Календарь тренировок на неделю: план из расписания, факт из `trainings`. Факт важнее плана; план никогда не становится фактом. Для плановой тренировки можно раскрыть список упражнений.
5. Тренировки за выбранный день.
6. Итоги недели: средние ккал и белок (прошедшие дни с записями; сегодня — только если день закрыт), число тренировок; по дням — ккал и БЖУ, оценка, статус, тренировка. По нажатию на день открывается этот день.
7. Сбоку: вес (последнее значение, изменение к прошлому, график, цель из `settings`) и незакрытые дни за 14 дней.

## Код
| Файл | Что внутри |
|---|---|
| `app/page.tsx` | Экран целиком |
| `app/useJournal.ts` | Загрузка, кэш, статусы `loading / ok / offline / signed-out` |
| `app/Login.tsx` | Форма входа |
| `app/WorkoutPlanner.tsx`, `app/TrainingJournal.tsx` | Календарь тренировок и тренировки за день |
| `lib/supabase.ts` | Сессия, вход, чтение таблиц |
| `lib/cloud.ts` | Перевод строк базы в снимок, порядок строк |
| `lib/training.ts` | Сведение плана и факта в один `TrainingDay` |
| `lib/workouts.ts` | Шаблоны тренировок и постоянное расписание |
| `lib/food.ts` | Расчёт КБЖУ порции и дня |
| `tests/*.test.ts` | Unit-тесты (`npm test`) |

## Проверка изменений
- `npm test`, `npx tsc --noEmit`, `npm run build`. CI запускает всё это на каждый push в `main` и по `workflow_dispatch`.
- Тесты пишутся только на синтетических данных, без копий личного дневника.
- В облачной сессии агента доступ к npm, `*.github.io` и `*.supabase.co` может быть закрыт. Тогда проверяй через CI (`gh run list`, `gh run view <id> --log-failed`).
- После push проверь, что прошёл деплой Pages, и только потом говори, что сайт обновлён.
